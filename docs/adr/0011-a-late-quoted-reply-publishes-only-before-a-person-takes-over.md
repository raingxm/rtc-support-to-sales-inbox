# 停止等待之后，只有接手前的文档原句才进入会话

客户提问后，模型若没在这次等待里返回，工单进入待人工处理，此时不发回复。客户入口不显示这个状态。

此后才到达的结果，只有在支持人员还没发出本轮第一条回复、会话仍是这次分析所依据的那些客户消息、并且带有文档原句时，才发成回复，工单离开待人工处理。没有文档原句的不发，工单继续待人工处理。客户在这之后又发出一条消息时，针对更早会话的迟到结果丢掉，不留作草稿，也不进入会话。同一次结果里的分流建议也丢掉。尚未确认的分流保持原样，直到包含最新一条客户消息的分析到达；还没有任何分流时就先空着。系统改等包含最新一条客户消息的结果。会话没变、人工接手已经开始时，迟到结果留在支持入口作草稿。客户又发出一条消息后，这份还没发出的草稿也丢掉，包括支持人员已经改过的，并且不换成一份新的草稿。支持人员按最新的客户原话自己写回复。分析仍可更新尚未确认的分流。交还不把草稿发成回复。交还之后，系统可以先回复的是客户的下一条消息。人工接手期间客户发出的那条消息，系统也不补发成回复。

待人工处理的等待时长从客户最后一次开口算起。系统发出的「答不了」不把这段时长清零。

模型在等待时限内返回的，仍按原规则。有文档原句就回复。打不开公开文档时，回复只说明答不了。

接手前把带文档原句的迟到结果发出去，客户等到的仍是一条回复。已经有人接手后再发进会话，客户会在同一次对话里看到两种说法。
